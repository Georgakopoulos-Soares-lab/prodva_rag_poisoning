# Retrieval-Corpus Poisoning of ProDVa

This repository studies whether inserting a handful of text–protein records into the
supporting retrieval corpus of **ProDVa** (a text-guided protein design model) can steer the
proteins it generates toward an attacker-chosen, benign off-target function — and, just as
importantly, when it *cannot*.

Everything here is **in silico**. The payload is a benign laboratory-style protein domain; no
sequence was synthesized or ordered. See "Safety" in [docs/RESULTS.md](docs/RESULTS.md).

- **What we found:** [docs/RESULTS.md](docs/RESULTS.md)
- **What was and wasn't done:** [docs/PROGRESS.md](docs/PROGRESS.md)

## Repository layout

```
env/                 environment build (conda + pinned pip) and shared settings
  project_env.sh       paths, SLURM account, offline caches, faiss shim  (source this in every job)
  setup_gen_env.sh     builds the `prodva-poison-gen` conda env
  requirements-gen.txt pinned pip dependencies
  shims/               sitecustomize that no-ops ProDVa's GPU-only faiss call (we use faiss-cpu)
tools/               the pipeline (one script per step; see "Reproduce" below)
slurm/               the four canonical batch jobs
configs/             baseline_eval.yaml (frozen decoding config for the clean baseline)
artifacts/attack/    attack inputs, tracked: target lists, poison records, payload  (small JSON)
docs/                RESULTS, PROGRESS, verified_facts, code_map, glossary
figures/             result figures (Nature-style; generated by figures/*.py via plotting/)
plotting/            shared publication style (style.py, colors.py)
```

Large, regenerable things are git-ignored: `artifacts/upstream/` (the ~11 GB download),
`indexes/`, `runs/`, `logs/`, caches, and the upstream clone `third_party/ProDVa/`.

## Environment / hardware

Developed on **TACC Lonestar6**: SLURM, A100-40GB GPUs, conda. Any SLURM cluster with one
A100-class GPU works. Two constraints shaped the tooling:

- **Compute nodes have no internet**, so all downloading/installing happens on a login/VM node
  and the GPU jobs run fully offline from local copies.
- The GPU faiss build needs a newer glibc than LS6 provides, so we use **faiss-cpu**; retrieval
  is an exact `IndexFlatL2`, so results are identical. ProDVa's one GPU-transfer call is turned
  into a no-op by `env/shims/sitecustomize.py`.

The SLURM allocation is set in `env/project_env.sh` (`PRODVA_POISON_ACCOUNT`, **uppercase**).

## Reproduce

All paths and the conda env are defined in `env/project_env.sh`; every job sources it.

**1. Clone the upstream model code at the pinned commit**
```bash
git clone https://github.com/sornkL/ProDVa third_party/ProDVa
cd third_party/ProDVa && git checkout ff2d41c8be77a27c116c2b70fc1255441ede4107 && cd -
```

**2. Build the environment** (login/VM node, has internet)
```bash
bash env/setup_gen_env.sh          # creates the prodva-poison-gen conda env
```

**3. Download the checkpoint, dataset and retrieval embedder** (~11 GB, login/VM node)
```bash
python tools/download_upstream.py --what all      # -> artifacts/upstream/{checkpoint,dataset,embedder}
```

**4. Confirm the retrieval encoder and reproduce the clean baseline**
```bash
sbatch -A "$PRODVA_POISON_ACCOUNT" slurm/s1_baseline.slurm
# verify_encoder confirms NeuML/pubmedbert-base-embeddings built the shipped index (cosine 1.0),
# then generates 500 clean sequences.
```

**5. Build the attack inputs** (deterministic; small JSON, already tracked but regenerable)
```bash
python tools/select_targets.py             # 10 DEV + 30 EVAL targets
python tools/make_distinct_poisons_dev.py  # hand-crafted distinct poisons for the 30 EVAL targets
python tools/make_eval100.py               # 100 EVAL targets + near-dup/distinct/random poisons + free-text queries
```

**6. Run the full n=100 study** (one job: retrieval sweep to m=1500 + end-to-end generation + CIs + figures)
```bash
sbatch -A "$PRODVA_POISON_ACCOUNT" slurm/full_run_100.slurm
```

**7. (Optional) corpus-size analysis** used to attribute the benchmark's robustness to corpus density
```bash
sbatch -A "$PRODVA_POISON_ACCOUNT" slurm/density_ablation.slurm
```

Outputs land in `runs/attack/*.json`, `runs/e2e100/`, and `figures/`.
`tools/submit_with_retry.sh` is a small helper for submitting from a login node over SSH.

## The pipeline (`tools/`), in the order it runs

| step | script | does |
|---|---|---|
| download | `download_upstream.py` | fetch checkpoint, dataset, embedder |
| verify | `verify_encoder.py` | prove which encoder built the shipped index |
| targets | `select_targets.py`, `make_eval100.py`, `make_distinct_poisons_dev.py` | build target lists + poison/hub inputs |
| deploy | `build_poison_deployment.py` | add poisons to a copy of the index (Route A) |
| minimal maps | `build_minimal_mappings.py` | tiny, exact seq/fragment maps (performance-only) |
| hubs | `gen_hub_records.py` | universal hub records for Attack U |
| generate | `fast_attack_driver.py` | load once, matched-seed clean-vs-poison generation |
| retrieval | `attack_analysis_100.py` | Poison@16 + universal budget sweep + figures + CIs |
| metrics | `measure_poison_at16.py`, `measure_universal_capture.py`, `measure_divergence.py`, `measure_gain_of_function.py`, `analyze_ci.py` | capture, change-from-clean, gain-of-function, bootstrap CIs |
| corpus size | `density_ablation.py` | retrieval-only capture vs corpus size |
| checks | `verify_equivalence.py` | fast harness is bit-identical to `dvagen eval` |
